# 图片优先预览

检索和整理的结果必须先让用户看到实际图片，再提供文件名、路径和标签。文件名是辅助信息，不能代替图片预览。

## 渲染要求

1. 用户要求“看图、预览、确认候选”时，先通过 `cloud-access` 取得真实原图引用，并把原图作为当前回复里的原生图片内容展示。不要只交付文件卡片，也不要只输出文件名 chip。
2. 每张原图以图片为主视觉；文件名、云盘路径和标签放在图片下方或可展开详情中。缩略图只能用于索引阶段的快速筛选，不能作为用户要求查看原图时的替代品。
3. 候选较多时分批展示原图，先展示当前批次或代表性原图，再提供其余批次；contact sheet 只做总览和追溯附件，不能冒充原图预览。
4. `show_widget` 使用带真实图片引用的 image tile/grid；如果组件只能渲染文字卡片，就不要把它当作图片预览，改用原生图片附件。文件名列表不能冒充图片预览。
5. `nexus.deliver_files` 交付原图预览包、contact sheet、manifest 和报告是追溯手段，不能替代当前回复中的原图展示。

## 检索结果顺序

```text
实际原图 → 一句检索结论 → 路径/文件名/标签详情 → contact sheet、manifest 和报告文件
```

整理结果还要在每张图旁标出“候选 / 目标 / 状态”；执行前只展示候选和拟执行目标，确认后再展示执行结果。不得先展示长文件名列表再把图片藏在附件卡片下面。

## 失败处理

如果原图引用不存在或当前对话无法渲染图片，先重新取得原图或明确报告原图预览失败；不能用“已生成 contact sheet”作为原图已经展示的证明。

## 文件生命周期

- 缩略图、contact sheet 和需要在对话中展示的原图副本必须落在当前 workspace 的 `.cloud-photo/` 下（例如 `.cloud-photo/thumbnails/`、`.cloud-photo/organize/preview/`），不能只放在 `/tmp` 或命令进程的临时目录。
- 生成预览前逐项检查文件存在、大小大于零且 MIME 类型是图片；渲染引用必须指向这些持久路径或当前轮次有效的图片附件。
- `/tmp` 只允许作为云盘下载的中转目录。下载完成后必须复制到 `.cloud-photo/`，再生成图片附件；任务结束后清理中转目录不得影响已经交付的预览。
