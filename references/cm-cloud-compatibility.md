# cm-cloud-manage 版本选择

当前 `cloud-photo` 采用 `@org-vt43r0t0/cm-cloud-manage` **2.0.0**。

## 结论

2.0 更适合照片索引：搜索、列目录、详情和下载覆盖当前账号的整个个人云；可以从个人云根读取照片元数据和图片，再把 manifest、缩略图和报告写入智能体专属目录。1.0.6 的下载源文件也受沙箱限制，沙箱外照片必须先复制到沙箱再下载，索引全盘照片时会增加一次云端复制。

两版都不能把云端文件真正移动、删除或改名。2.0 的文件范围明确排除了 `move`、`delete`、`rename`；1.0.6 实际命令只有 `copy`，没有 `move`/`rename`/`delete`。因此“帮我整理照片”必须拆成两类可执行结果：

- **整理到相簿**：先检索和视觉复核，再调用 2.0 的 `album create --fileRefs` 或 `album add`。原文件位置不变。
- **整理到文件夹**：只能复制到智能体专属目录及其子目录；不能把原文件从个人云任意目录移走。复制是一次云端写操作，需要用户确认，并按回执对账。

## 能力对照

| 能力 | 1.0.6 | 2.0.0 | cloud-photo 采用方式 |
| --- | --- | --- | --- |
| 全盘文件名/类型/时间/大小检索 | 支持 | 支持，参数和分页更完整 | 索引模式扫描个人云 |
| 全盘列目录 | 支持 | 支持，个人根/专属根区分更明确 | 读取可信 fileRef |
| 全盘下载 | 不支持，沙箱外先 copy | 支持个人云任意位置下载 | 直接取得候选图片 |
| 上传/建目录 | 只能沙箱 | 只能智能体专属目录 | 写 `.cloud-photo/` 到专属目录 |
| 复制 | 支持，源可全盘、目标沙箱 | 支持，源可全盘、目标专属目录 | 文件夹整理的替代动作 |
| 真正移动/删除/改名 | 不支持 | 明确不支持 | 不调用、不伪装成功 |
| 相簿创建/加图 | 不在 1.0.6 文件命令中 | 支持 `album create` / `album add` | 相簿整理的首选 |

## 授权边界

“全盘读取”不等于“全盘写入”。2.0 的授权是智能体专属目录写入范围：

- `files search`、`files list`、`files info`、`files download` 可读取当前账号的个人云。
- `files upload`、`files mkdir`、`files copy` 的目标必须是智能体专属目录及其子目录。
- 相簿 API 是独立的相簿资源，不等同于把文件移动到某个云盘目录。

因此索引阶段可以覆盖个人云里的照片；索引产物统一落在专属目录；整理阶段返回“相簿加入”或“复制到专属目录”的计划，不能生成“移动原文件”的计划。
