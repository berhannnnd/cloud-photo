# 整理结果证据包

演示或用户查看整理结果时，不要只给一张云盘页面截图，也不要直接把大量原图塞进对话。每次整理输出一个“证据包”，让视觉效果和可核对事实同时出现。

## 对话中的一条结果

### 1. 结果摘要

用普通文字先给出真实结果：

```text
已整理 24 张照片：18 张加入「旅行」相簿，6 张暂未确定。
原照片位置未改变。
```

数量必须来自执行回执；`UNKNOWN`、未执行和失败不能算入成功数。

### 2. 图片网格 / contact sheet

把本次实际处理的照片缩略图直接展示在对话正文中。图片是主内容，文件名只是 caption；只展示文件名列表、路径列表或生成文件卡片都不算完成预览。

### 3. `show_widget` 整理卡

widget 展示结构化映射，不负责访问云盘：

- 顶部：成功、部分完成、待确认数量
- 过滤器：全部 / 已加入相簿 / 已复制 / 待确认 / 失败
- 每张候选的文件名、原路径、主要标签、目标相簿/目录和执行状态
- 一行展开详情：原路径、扫描批次、处理时间
- 如果有稳定的云盘深链接，显示“打开原图”；没有时显示云盘路径和 file_id，不伪造 URL

整理卡里的图片只放少量代表性缩略图；按钮只做本地筛选和详情展开，不能直接执行云盘写操作。

### 4. 缩略图 contact sheet

把本次实际处理的照片缩略图生成一张或多张 contact sheet，每格包含：

```text
缩略图
文件名
主要视觉标签
目标相簿/目录
状态
```

contact sheet 用 Nexus 原生图片附件交付。它是“看效果”的证据；原图不需要全部上传到对话。需要核对细节时，再按 `asset_id` 取得单张原图。

### 4. 可追溯报告

通过 `nexus.deliver_files` 交付：

- `organize-report-<run_id>.json`：逐项事实、原 `source_ref`、目标引用、回执状态
- `organize-report-<run_id>.html`：适合人查看的离线报告（可选）
- `contact-sheet-<run_id>-<part>.png`：缩略图总览
- `manifest-<scan_id>.jsonl`：本次使用的索引版本

报告内部仍可保留不可见的稳定文件引用供系统回查；用户可见字段只展示路径。

报告中的链接优先级：

1. API 返回的稳定云盘深链接；
2. 云盘路径；
3. 需要分享链接时，用户明确要求后再调用分享能力并走确认流程。

不要把临时下载 URL 当成长期链接，也不要默认给每张照片创建公开分享链接。

## 推荐的演示顺序

1. 先展示整理前的少量照片集合或原始目录范围。
2. 展示 contact sheet，让观看者直接看到猫、旅行、人物等视觉标签确实对应照片。
3. 展示 `show_widget` 的“候选 → 目标 → 状态”映射。
4. 展示一两条可回溯链接和完整报告文件。
5. 最后说明原图是否移动：相簿整理是不移动原文件，文件夹整理是复制到专属目录。

这样演示同时证明“模型看懂了图片”“动作确实执行了”“每张图片可以追溯”，而不是只证明页面出现了一个成功提示。
