# 整理结果与回溯

结果回答：用了哪些照片、什么规则、排除了什么、写到哪里、哪些成功/失败/未知。执行事实来自 cm-cloud-manage 公开回执，展示事实来自宿主媒体通道，分别报告。

## 保存的证据

- 搜索：原始与规范条件、范围、页数、已加载数、page.total（可为空）、page.complete、来源。
- 筛选：输入/输出结果集与版本、成员 asset_id、排除理由、未知字段、规则与标签版本。
- 计划：固定候选版本、分组维度、目标类型/名称/引用、逐项动作、摘要和授权范围。
- 执行：每组/每批对应的 operationRef、顶层状态、逐项结果、实际名称/路径/资源引用、成功/失败/未知/未执行项。
- 回溯：原会话引用、结果集、计划版本与操作映射；恢复所需的身份与短期引用绑定记录。

本地稳定 asset_id 与短期 fileRef 分开；不存凭据、确认 token 或签名下载 URL。照片数与写入动作数分开统计，同一照片进入多个相册时二者不同。以上完整对象仍待适配器实现，现有脚本不会自动生成整条证据链。

## 状态与恢复

使用 CLI 顶层 SUCCESS/EMPTY/PARTIAL/RUNNING/CONFIRMATION_REQUIRED/AUTH_REQUIRED/REJECTED/FAILED/UNKNOWN；不能套用另一个后台的数字任务状态。operationRef 表示操作引用，单独出现不代表完成；nextAction 决定底层允许的续办。

只在明确返回成功事实时报告相应动作成功。PARTIAL 保留成功项，RUNNING 表示尚未完成，UNKNOWN 先核对。没有 operationRef 的查询不能调用原操作恢复；有引用时按底层协议查询，不无休止轮询。error.retryable 也不授权重复提交写入。

建册成功加图失败保留 albumRef，只恢复加图；新条件生成新计划，不覆盖已运行动作。没有公开取消/撤销能力，不能在对话中虚报取消或回滚。空集合、缺数据、服务错误分别提示，空计划不创建相册/目录。

## 结果交付

普通相册通过 album.files 对账，文件夹通过 files.list 对账，处理引用变化时沿用资产映射规则。只展示回执中真实的路径和链接，不推测跳转 URL。album.share 会创建分享链接，不能为展示内部结果而默认调用。

宿主有任务卡或媒体能力时使用它；没有时提供准确的文字状态和结果摘要。不编造进度百分比，不把生成预览图片说成用户端已展示，不承诺没有持久执行机制支持的后台自动跟踪。
